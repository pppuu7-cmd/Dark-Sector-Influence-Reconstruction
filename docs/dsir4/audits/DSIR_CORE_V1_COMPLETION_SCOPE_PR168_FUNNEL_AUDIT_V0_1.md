## Audit findings

### 1. The proposal is prospective governance, not terminal science authority

The new Core-v1 document is explicitly labeled `PROSPECTIVE FREEZE-SCOPE CONTRACT`. That is compatible with the current funnel only if it remains a roadmap/release-scope proposal and does not itself open any scientific gate.

The phrase `Authorized critical path` is too strong in the current draft. The listed path includes production reference closure, G5/statistical closure, covariance, whitening, nuisance, quotienting, adapter semantics, and future decision semantics. Current terminal authority does not authorize those stages now. They can be listed as prospective dependencies, but each scientific/statistical stage must remain unopened until reached through the strict terminal-authority chain.

### 2. F1 correctly preserves the current next admissible gate

The F1 text correctly requires prospective freezing of the complete 107-row denominator, exact inputs, forced non-AVX512 baseline, exact-target-union construction, solver accounting, thresholds, fail-closed rules, and an independent audit before terminal authority. It also forbids target-local/ad-hoc/post-result node unions. This is consistent with the current V0.25 correction authority.

However, PR #168 does not itself supply the required F1 preregistration or immutable contract. Full 107-row execution therefore remains closed.

### 3. Downstream F2-F7 must not inherit authorization from the scope document

The proposal can define which capabilities a future Core release should eventually close, but it must not be read as authorization to open F2-F7 after merge. In particular, covariance, whitening, nuisance, statistical/model comparison, and `NEW_MODEL_REQUIRED` eligibility remain future gates requiring their own prospective definitions and upstream terminal authorities.

A release-scope document is not a substitute for a funnel authority object.

### 4. Readiness relabeling must not erase current scientific accounting

The proposed three-dimensional readiness split can be useful, but no denominator, calculation rule, migration rule, or initial values are frozen in PR #168. Therefore it cannot yet replace the current authoritative `ARTICLE3_REPOSITORY_READINESS: 68%` and scientific frontier `67%`.

If adopted, `DSIR Core v1 FROZEN` must be explicitly separated from scientific closure, publication readiness, and Polygon scientific coverage. Core methodology/executable readiness reaching 100% must not be presented as 100% scientific closure while G7/G8/G9 or other frozen-denominator science gates remain open.

### 5. Recovery/process synchronization is incomplete

PR #168 changes `docs/CURRENT_PROCESS.md` but not `docs/RECOVERY_LATEST.md`. If merged as drafted, a clean-session reconstruction would see a new Core-v1 objective in the process ledger while recovery remains unaware of the scope contract and still carries the current readiness/frontier accounting. The scope change therefore needs recovery reconciliation if/when it is accepted.

### 6. No threshold tuning or result rewriting found

The PR does not change the V0.25 scientific threshold `<1e-3`, technical reproducibility threshold `<1e-5`, exact binding `<=1e-12`, production `h=1e-4`, sampling `0.00035`, or `tol_perturb_integration=1e-12`. It does not mutate the V0.25 terminal classification or provenance correction. No post-result threshold tuning was found in the reviewed diff.

## Alternative explanations / counterexamples

The strongest failure mode is administrative rather than numerical: a future agent could read the branch `CURRENT_PROCESS.md` sentence `The active objective is now...` plus the heading `Authorized critical path` as a blanket authorization for F2-F7. That would create an illegal gate skip even though the text elsewhere says F1 is first. The counterexample is immediate: the current terminal V0.25 correction authority explicitly forbids reading covariance/whitening/nuisance and authorizes only the prospectively frozen full-Layer-B numerical replay definition.

A second failure mode is treating green PR CI as evidence that the Core-v1 contract itself is validated. Run `34910842417` executes an unrelated pre-existing additive-projection workflow; its success cannot validate the new governance semantics.

A third failure mode is declaring progress by relabeling readiness. Without frozen denominators and migration rules for the new readiness dimensions, replacing the current 68%/67% figures would be administrative bookkeeping, not scientific closure.

## Required qualifications before this scope can be treated as authoritative

1. Rename or explicitly qualify `Authorized critical path` as a prospective planned dependency path. State that only the current F1 definition is the next admissible gate and that F2-F7 require separate future terminal authorization.
2. Preserve explicit language that the 107-row replay is not executable until a new preregistration and immutable contract are committed.
3. Reconcile `docs/RECOVERY_LATEST.md` if/when the Core-v1 scope is merged.
4. Keep current readiness/frontier values authoritative until new readiness dimensions have frozen denominators, calculation rules, migration rules, and initial values. Never equate `DSIR Core v1 FROZEN` with scientific closure or physical dark-sector inference.
5. Treat PR CI run `34910842417` and artifact `10374282750` as incidental regression evidence only; they are not a scope-validation or scientific authorization artifact.
