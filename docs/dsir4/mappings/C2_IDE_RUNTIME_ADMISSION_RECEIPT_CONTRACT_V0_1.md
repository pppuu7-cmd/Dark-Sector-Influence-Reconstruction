## Receipt purpose

A runtime receipt is an admission object for a *candidate raw record set*. It is not itself a scientific prediction and cannot be interpreted as a model PASS/FAIL.

The receipt MUST bind at minimum:

1. `hypothesis_id`;
2. exact solver repository + commit;
3. exact instrumented source identity and diagnostic-hook identity;
4. exact executable/build identity used for the producer;
5. exact runtime command/config identity and baseline cosmology identity;
6. exact frozen alpha/beta model-point identity;
7. exact ordered coordinate manifest and units;
8. `packet_count=28` and `aggregate_bytes=1792`;
9. SHA-256 of the raw aggregate before decoding/mapping;
10. producer run/job identity and terminal status;
11. artifact identity/digest when transported through GitHub Actions;
12. explicit booleans `raw_record_set_admitted`, `decoded=false`, `mapped=false`, `prediction_ready=false` at this boundary.

## Fail-closed admission rules

Reject as infrastructure / `INVALID_FOR_SCIENCE` and never scientific FAIL if any of the following occurs:

- producer is nonterminal, cancelled, skipped, or lacks a complete artifact;
- packet count, aggregate byte count, ordering, coordinates, units, or frozen identities differ;
- aggregate SHA-256 is absent or mismatched;
- any packet has been decoded, transformed, interpolated, filtered, reordered, duplicated, deleted, averaged, smoothed, or tolerance-rescued before receipt admission;
- provenance cannot bind the exact producer and artifact;
- synthetic fixture bytes are presented as runtime data;
- any downstream scientific gate influenced runtime coordinates, parameter steps, or record selection.

A physical branch violation (`rho_idm <= 0` or `rho_iv < 0` where the frozen branch requires otherwise) is `OUTSIDE_DOMAIN` for the affected frozen point, not infrastructure failure and not observational scientific FAIL.

Missing immutable provenance required for the frozen tangent steps or matched solver settings remains `NOT_YET_TESTABLE`.
