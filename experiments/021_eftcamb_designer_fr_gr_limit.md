# Experiment 021 — H-EFTCAMB designer-f(R) GR-limit calibration

Date: 2026-08-24
Status: CALIBRATION IN PROGRESS
Gate: MG-S0, prerequisite for completing G3B

## Scientific question

Can the official H-EFTCAMB designer-f(R) implementation be embedded into the DSIR v0.1.1 response basis with a controlled GR limit?

The production perturbation response is

\[
r_\Delta(k,z)=\ln\frac{P_\Delta^{\rm model,S}(k,z)}{P_\Delta^{\rm ref,S}(k,z)}.
\]

Here both numerator and denominator are generated by the same H-EFTCAMB solver lineage `S`. For the first calibration we use z=0 and the frozen DSIR linear-core nodes

\[
k=\{0.001,0.003,0.01,0.03,0.1\}\;h/{\rm Mpc}.
\]

## Upstream implementation

Pinned official source:

`EFTCAMB/EFTCAMB@16d9c4e9f85751e30efd0a53b177941713078904`

from branch `eftcamb`.

Upstream author controls establish:

- GR: `EFTflag=0` (`fortran/eftcamb_test/parameters/1_EFT_GR.ini`);
- designer f(R): `EFTflag=3`, `DesignerEFTmodel=1`, `EFTwDE=0`;
- `EFTB0` is the designer-f(R) amplitude;
- upstream examples include `EFTB0=1` and `EFTB0=1e-4`.

`EFTwDE=0` keeps the designed background on the LambdaCDM expansion history, so the intended discriminator is perturbative/structure response rather than a background H(z) shift.

## Calibration sweep

Run matched GR plus

\[
B_0=10^{-2},10^{-3},10^{-4},10^{-5},10^{-6},10^{-7},10^{-8}.
\]

For each value compute

\[
r_\Delta(k;B_0)=\ln\frac{P_\Delta(k;B_0)}{P_\Delta^{GR}(k)}.
\]

The expected control behavior is

\[
\lim_{B_0\to0}r_\Delta(k;B_0)=0.
\]

No hard tolerance is imposed on the first run. A hard threshold may be frozen only after observing the convergence regime and numerical floor, followed by a separate untouched rerun.

## Additional diagnostics

Record:

1. `max_k |r_Delta|` over the five frozen nodes;
2. node-wise response versus B0;
3. log-log slope of the maximum response versus B0;
4. change in response between successive B0 values;
5. upstream build SHA and recursive submodule SHAs;
6. author GR and designer-f(R) smoke-test logs.

## Failure rules

- A build/configuration failure is infrastructure/implementation failure, not a physical rejection of f(R).
- If the response fails to trend to zero with B0, do not tune the DSIR threshold; inspect stability flags, parameter semantics, or the relevant solver branch first.
- Do not use the historical BZ quasi-static toy to patch missing low-k full-solver results.
- Do not admit H-EFTCAMB into the six-family production matrix until MG-S0 has a separate pre-frozen hard PASS.

If convergence is clean, freeze a conservative GR-limit tolerance before a fresh run. Then define MG-S1 with a nonzero stable B0 and compute the full same-solver `r_Delta(k,z)` on every frozen DSIR redshift node.
